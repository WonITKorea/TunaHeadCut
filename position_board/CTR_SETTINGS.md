# CTR ClampRing 설정 반영 내역

원본: `C:\Users\user\CTR_ClampRing\CTR.pbp2`, `SampleData.prm2`.
초기 대상: [TunaHeadCut.pbp2](TunaHeadCut.pbp2), [TunaHeadCut.prm2](TunaHeadCut.prm2).
현재 모터 시험용 운용 파일: **[TunaHeadCut-MotorBench.pbp2](TunaHeadCut-MotorBench.pbp2)**.

현재 MotorBench는 사용자 선택에 따라 **1:1 전자기어, 최소 -5598206 / 최대 11179010, 전체 4바퀴**입니다.
속도는 419430 count/s(약 6 rpm), 중간 기준점은 2790402입니다.
기존 ABS 등록 데이터를 보존하고 리미트/속도와 포인트만 변경하여 Flash에 저장했습니다.
[현재 적용 기록](backups/four_turns_20261013_135505/apply_result.json).
아래 초기 설정·등록 기록의 좁은 범위는 과거 값이며 현재 MotorBench에는 적용하지 않습니다.

**프로젝트 파일 수정과 실제 보드 RAM 적용·System Start·읽기 검증을 완료했습니다.**
사용자가 기존 2786203~2794600 좌표·1:1 전자기어 유지, EMI/EM2 및 LSP/LSN 미연결을 확인한 조건입니다.
이후 모터가 기구에서 분리되어 있고 임의 좌표를 등록해도 된다는 사용자 확인에 따라,
현재 모터 위치를 중간 좌표 `2790402`로 등록하고 Flash 저장 및 보드 재시작 후 복원을 검증했습니다.
위치 이동 명령은 보내지 않았습니다. 등록 과정의 서보 ON/OFF 시 모터 피드백 변화가 관찰되었습니다.

## 최초 등록·복원 기록

- RUNNING, 서보 OFF, `home_required=false`, `encoder_error=false`, 알람·경고·강제정지 없음.
- MotorBench 기준 좌표 `2790402`, 복원 유효 `0241=0001`; 원본 초기 프로젝트는 기준점 미등록 상태로 보존.
- 보드가 생성한 `024D=4312`, `024E=1E36`, `024F=0032`(16진수)를 실제 읽어서 저장.
- Flash 저장 → 보드 재시작 → Flash 읽기 → System Start 후 파라미터 1054개 일치.
- 피드백 `2791185 → 2791187`(2 count 차이), 실제 전원 OFF/ON 시험은 미실시.
- [기준점 등록 기록](backups/motor_bench_midpoint_20261013_130210.json), [Flash 복원 기록](backups/motor_bench_flash_restore.json).

분리된 모터의 서보 OFF 후 위치 변화가 기존 상한을 넘지 않도록 기준 좌표를 범위 중간에 두었습니다.
이는 실제 기구 보정이 아닙니다. 기구 연결 후에는 실제 Start/End와 정지·리미트 배선을 기준으로 다시 설정합니다.

## CTR과 초기 프로젝트 비교

| 항목 | CTR 원본 | TunaHeadCut 적용값 |
|---|---|---|
| 보드 / ID / 채널 | MR-MC240N / 0 / 1 | 동일 |
| 연결 / Utility2 모드 | PCIe / Test | 동일 (`CONNECTION=0`, `TOOL_MODE=1`) |
| 파라미터·포인트 연결 | `POSITIONING` 및 `PROJECT_FILE` | 동일 구조, TunaHeadCut 파일명 사용 |
| 제어 축 | 축 1 사용 | 축 1 사용, 축 2~32 미사용 |
| 축 번호 지정 `0203` | 1 | 1 (축 할당은 기존 자동 설정 유지) |
| 제어 옵션 `0200` | `0001` | `1001`: 실제 제어, 초 단위 속도, 기준점 유효성 확인 |
| 전자기어 CMX / CDV | 4194304 / 4000 | 1 / 1, 기존 좌표 단위 유지 |
| 속도 배율 `020E/F` | 1000 | 1 |
| 속도 상한 `0222/3` | 3000 (CTR 속도 단위) | 초기 프로젝트: 200 count/s; 현재 MotorBench: 419430 count/s |
| 소프트 리미트 하한 / 상한 | 0 / 196000 (µm) | 2786203 / 2794600 (count) |
| 센서 입력 `0219` | `0303`: 센서 미연결, LSP/LSN 무효 | 동일 |
| 외부 강제정지 `000E` | `5AE1`: 입력 무시 | 동일; 소프트웨어 SEMI 정지는 유효 |
| PA04 `1103` | `2100`: EM2/EM1 입력 미사용 | 동일 |
| ABS `1102` | `0000`: 미사용 | `0001`: 사용, 배터리 연결 확인됨 |
| 최초 기준점 등록 `0240` | `0002`: Data set 방식 | 동일, 홈 센서 탐색 없음 |
| 기준 좌표 `0246/7` | 0 | 2794600, 실제 Start 위치를 확인한 뒤 등록 |
| 복원 데이터 `0241`, `024D~024F` | 0 | 미등록 상태 유지 |

CTR의 4mm 리드·모터 직결 기구에서는 1 명령 단위가 1µm입니다.
그 전자기어만 복사하면서 기존 2786203~2794600 숫자를 그대로 사용하면 이동량과 좌표 해석이 바뀝니다.
따라서 사용자 확인에 따라 기존 좌표 범위와 1:1 전자기어를 유지했습니다.
CTR의 0~196mm 스트로크도 이 장비의 실측 범위로 간주하지 않았습니다.

소프트웨어 스트로크 리미트는 기준점 등록 완료 후 유효합니다.
초기 프로젝트를 저장하는 것만으로 절대 좌표 기준이 완성되지는 않습니다. MotorBench에는 이후 실제로 등록한 데이터가 들어 있습니다.
최초 기준점 등록과 재기동 후 복원 절차는 [README.md](README.md)를 따릅니다.

## 최초 보드 적용 이력 (기준점 등록 전)

적용 직전의 [백업 및 적용 계획](backups/ctr_apply_plan_20261013_124332.json)에는
시스템 파라미터, 축 1 제어·MR-J4 서보 파라미터, 나머지 축의 제어 옵션 총 1054개와 포인트 0~2의 기존 데이터가 있습니다.
이는 전체 다축 복구용 Utility2 프로젝트가 아닙니다. 당시 시스템은 `0001`(시작 전), 축 1~32 제어 미사용, Servo Ready/운전 OFF였습니다.

[적용 결과 기록](backups/ctr_apply_result_20261013_124332.json):

- 변경된 파라미터 15개와 절대 포인트 0~2 전송 후 일치 확인.
- System Start 후 1054개 파라미터 다시 비교, 불일치 0개.
- 시스템 `000A`(RUNNING), 외부 EMI 입력 미사용 상태 `EMID=ON` 확인.
- System Start 직후 시스템·서보·운전 알람 코드는 모두 0이었으나, 이후 재접속 점검에서 서보 `AL.25.1`이 확인됨. 시스템·운전 알람 코드는 0 유지.
- Servo Ready/운전 OFF, 소프트웨어 강제정지 `SEMI=ON` 및 `forced_stop=true` 유지.
- 최초 피드백 0, 재점검 피드백 2, `home_required=true`, 기준점 완료 OFF. 미등록 피드백으로 기존 좌표 범위를 재설정하지 않음.
- 재점검 `encoder_error=true`, `servo_alarm=true`, `servo_warning=true`. ABS 기준이 유효하지 않아 이동 불가.

`AL.25.1`은 모터 엔코더의 절대위치 데이터 소실 알람입니다. 이번에는 PA03을 최초 ABS 사용으로 전환한 뒤 발생했습니다.
배터리 정상 연결·앰프 전원 재투입을 확인한 뒤, 실제 Start 위치가 확인된 상태에서 최초 기준점을 등록해야 합니다.
배터리 연결 사실만으로 배터리 전압이나 기존 엔코더 데이터의 유효성까지 확인된 것은 아닙니다.
알람을 강제로 지우거나 기준점 유효 비트를 임의로 설정하지 않았습니다.
자세한 상태는 적용 결과 기록의 `followup_checks`에 있습니다.

초기화·재부팅·Flash 저장·기준점 등록·서보 ON·이동 명령은 보내지 않았습니다.
RAM 설정은 전원 재투입 시 유지된다고 보장할 수 없으므로, 기준점 등록 후 보드에서 운용 파라미터를 읽어 저장해야 합니다.
현재 파일에는 유효한 기준점 복원 데이터가 없으므로 최초 등록이 끝난 뒤 이 초기 파일을 다시 전송하지 않습니다.

현재 설정은 외부 정지·리미트 입력 미연결의 모터 단독 시험 조건입니다. 기구 연결 후 운전 전 독립적인 비상정지 회로를 갖추고 입력 설정을 배선에 맞춰 검증합니다.
모터 분리 확인 후 등록 과정에서 소프트웨어 강제정지를 명시적으로 해제했습니다. Python 제어 코드는 이를 자동 해제하지 않습니다.
